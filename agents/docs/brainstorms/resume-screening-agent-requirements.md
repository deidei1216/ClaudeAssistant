# 简历筛选 Agent 需求文档

> 创建日期: 2026-04-10
> 状态: Draft

## 业务背景

人力外包公司的简历初筛流程：

```
简历池 → 初筛(Agent) → 人工复核 → 交付给客户 → 客户决策 → 面试安排
```

当前痛点：
- 人工初筛耗时，需快速过滤不合适候选人
- 简历交付给客户时，客户需要花费时间定位关键信息
- 缺乏标准化的筛选依据记录，难以追溯决策原因

## 目标用户

- **内部用户**：HR/招聘专员，使用筛选报告快速决策
- **外部用户**：客户方负责人，查看带批注简历快速判断候选人

## 核心需求

### 1. 简历筛选评估

综合评估以下维度：

| 维度 | 评估内容 |
|------|----------|
| 技能匹配 | 是否具备岗位要求的技能和工具使用经验 |
| 经验年限 | 相关领域工作年限是否达到要求 |
| 学历证书 | 学历、专业证书等硬性指标 |
| 项目经历 | 相关项目经验、行业背景 |
| 软技能 | 沟通能力、团队协作等（根据简历描述推断，需人工复核确认） |

> **AI 偏见风险提示**：软技能推断基于简历文字描述，可能存在主观判断偏见。人工复核时应特别注意：
> - 简历表达方式差异（如内敛型描述可能被低估）
> - 行业/地域术语差异导致的判断偏差
> - 对"软技能"结论存疑时，建议在面试环节重点验证

### 2. 输出策略

**统一输出**：带批注简历副本，内嵌筛选结论摘要

输出结构：
1. **首页摘要区**：
   - 筛选结论：通过 / 不通过 / 待定（需人工复核）
   - 维度评分：各维度量化评分（1-5 分）
   - 核心依据：结论的理由摘要（3-5 条）
2. **批注正文**：
   - 绿色批注（✓）：亮点信息
   - 黄色批注（⚠）：需关注项（问题点、缺失项）

**批注形式**：
- **PDF 优先策略**：所有简历统一输出为 PDF 批注副本（Word 文档先转为 PDF 再批注）
- PDF 批注使用 Annotation 注释功能（需引入 pdf-lib 或商业 SDK）
- 不修改原文内容，批注为叠加层
- **图标 + 颜色双标记**：确保色盲用户和打印场景可用

### 3. 灵活输入方式

#### 简历输入
- 支持单份简历处理
- 支持批量处理（多份简历一次提交，上限 20 份/批次）
- 支持格式：Word (.docx) / PDF (.pdf)

#### 岗位要求输入
- **手动输入**：自由填写岗位要求文本，适用于临时/特殊岗位
- **岗位模板库**：预定义常见岗位模板，快速选择调用

岗位模板内容：
- 岗位名称
- 必需技能清单
- 加分技能清单
- 经验年限要求
- 学历要求
- 其他硬性条件

### 4. 批量处理输出

批量处理时，每份简历输出统一格式（带批注简历副本），额外生成汇总表便于整体对比。

**处理策略**：并发处理（最多 5 个并行），显著缩短总处理时间。

当批量处理多份简历时：
- 输出汇总表（Excel 或 Markdown 表格）：候选人名单、筛选结论、评分概览
- 各简历独立输出：带批注的 PDF 简历副本

## 非目标

以下内容不在当前范围：

- 自动发送简历给客户（仅生成文档，人工决定交付方式）
- 面试安排或后续流程管理
- 与外部招聘平台集成
- 简历库管理或候选人档案存储

## 成功标准

1. **准确率**：Agent 筛选结论（通过/不通过/待定）与人工复核结论一致率 ≥ 80%（核心指标）
2. **筛选效率**：单份简历处理时间 ≤ 3 分钟（参考指标，准确优先于速度）
3. **客户满意度**：带批注简历减少客户阅读时间 ≥ 50%（基于反馈调研）
4. **模板库价值**：岗位模板库覆盖 ≥ 80% 的常见招聘岗位，且模板使用率 ≥ 60%（验证模板库实际价值）

## 技术约束

- Agent 定义存储于 `agents/resume-screening.md`
- 使用 Claude Sonnet 4.6 模型（平衡推理质量与成本）
- **PDF 优先策略**：所有简历统一输出 PDF 批注副本，Word 输入先转换为 PDF
- PDF 处理依赖：pdf-lib（开源，需低级 Annotation 操作）或 Nutrient（商业 SDK，开箱即用）
- 批量处理上限：单批次 ≤ 20 份简历

## 待确认事项

1. 岗位模板库的存储位置与管理方式
2. 简历文件的输入渠道（Discord 上传？本地文件路径？）
3. 输出文件的存储与命名规则
4. 评分算法的具体设计（加权？阈值判定？）
5. PDF 批注库选型：pdf-lib（开源，需低级操作）vs Nutrient（商业 SDK）
6. 并发处理错误隔离策略：单份失败是否中断批次？进度反馈机制？
